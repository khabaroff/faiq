# Как выложить это на VPS

Ниже простой вариант: один VPS, одна папка, один запуск pipeline.

## Куда класть проект

Рекомендую держать проект в одной папке, например:

```text
/opt/guides
```

Или:

```text
/srv/guides
```

Главное, чтобы путь был стабильный и понятный.

## Что должно лежать на VPS

Внутри папки должен быть весь проект:

- код;
- `data/`;
- `wiki/`;
- `docs/`;
- `tests/`;
- `.venv` или возможность создать его на месте;
- `.env` с секретами.

Секреты не коммитим. Они лежат только на VPS в локальном `.env`.

## Простой порядок установки

### 1. Подготовить систему

На VPS должны быть:

- `git`;
- `python`;
- `uv` или возможность поставить зависимости через него;
- доступ к сети, если pipeline ходит в LLM API.

### 2. Скопировать проект

Проще всего:

```bash
git clone <repo-url> /opt/guides
cd /opt/guides
```

Если ты не хочешь тянуть из git, можно просто закинуть папку целиком через `rsync`.

### 3. Создать окружение

Если проект использует `uv`, то обычно достаточно:

```bash
uv sync
```

Если нужен обычный venv:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 4. Положить `.env`

В `.env` должны быть:

- ключи к Azure/OpenAI;
- endpoint;
- все переменные, без которых pipeline не стартует.

### 5. Проверить ручной запуск

Перед автоматизацией надо один раз запустить вручную:

```bash
cd /opt/guides
./.venv/bin/python src/process_stream.py
```

Если запуск прошел, значит окружение собрано правильно.

## Как запускать по расписанию

Самый простой вариант - `cron`.

Пример:

```cron
*/15 * * * * cd /opt/guides && ./.venv/bin/python src/process_stream.py >> data/logs/cron.log 2>&1
```

Здесь важно две вещи:

- запуск идет из одной и той же папки;
- lock-файл не даст двум процессам идти одновременно.

## Как подкидывать новые материалы

Есть два простых варианта:

### Вариант 1. `data/inbox/`

Кладешь файлы в `data/inbox/`, потом запускаешь pipeline. После успешной обработки локальные файлы переезжают в `data/inbox_done/`.

### Вариант 2. `data/queue/inbox.txt`

Кладешь ссылки в очередь по одной строке.

Оба варианта можно держать вместе.

## Где смотреть результат

После прогона смотри:

- `wiki/extracts/` - готовые страницы;
- `wiki/_indexes/` - навигация;
- `wiki/log.md` - короткая история прогона;
- `data/logs/` - технические логи;
- `data/sources/` - сырьевые bundles.

## Что обычно проверять после запуска

1. Создались ли новые страницы.
2. Нет ли дублей.
3. Нет ли мусорных страниц.
4. Правильный ли заголовок.
5. Нормальный ли frontmatter.
6. Обновились ли индексы.
7. Нет ли ошибок в `data/logs/`.

## Если нужен более простой способ

Если не хочешь настраивать cron сразу, можно просто:

1. закинуть проект на VPS;
2. поставить `.env`;
3. руками запустить `process_stream.py`;
4. посмотреть, что получилось;
5. только потом добавить cron.

Это нормальный путь. Сначала сделать, чтобы оно работало вручную, потом уже автоматизировать.
